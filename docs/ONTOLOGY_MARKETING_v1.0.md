# マーケティング部 オントロジー定義書 v1.0(JOvAI)

## 0. 目的
マーケティングAIが「**1回目の購入者を2回目の購入者に変える**」ための世界模型。
広告で新規を買い続けない以上、この会社の成長はリピーターの厚みでしか説明できない。本書は顧客・希望条件・通知・問い合わせを構造化し、**一期一会の1点物ビジネスで反復購入が成立する回路**を定義する。

適用範囲:サイト運営・注文フォームの受付・問い合わせ・顧客・再購入導線。
- 商品ページの**内容と価格**は販売部が正本。本部門はそれをサイトへ反映する導管である。
- 個体 `K-####` は倉庫部、受注 `ORD-####` は販売部が正本。
- 顧客接点はすべてネット上で完結する。対面・電話による接客は存在しない。

## 1. 設計原則
1. **顧客データは目的と期限とセットで持つ**。持てるから持つ、をしない。
2. **待っている人を資産とみなす**。1点物では「探している条件」の登録が最強の需要予測。
3. **優遇は値引きではなく順番**。粗利を削らずに再購入を促す。
4. **知らないことは答えない**。個体にない情報で回答しない。
5. **反応は行動で測る**。開封や閲覧ではなく、注文・返信・登録で評価する。

## 3. クラス定義

### 3.1 顧客 `CUST-####` / 同意 `CONSENT-####`
`CUST` 属性:連絡先 / 区分(購入者・見込み) / 購入履歴 `ORD` 群 / 用途(分かれば) / 通知可否 / 初回接触日 / 最終接触日
`CONSENT` 属性:利用目的 / 取得日 / 保持期間 / 連絡手段の可否 / **撤回日**
規則:目的・保持期間・同意のない属性は保持しない。撤回されたら以後の `NOTIF` を止める。保持期間を過ぎた連絡先は削除する。

### 3.2 希望条件 `WANT-####`
属性:顧客 / 樹種 / 種別 / 寸法帯(下限・上限) / 用途(天板・棚板・カウンター) / 予算上限 / 等級の許容 / 登録日 / 有効期限 / 状態
状態:`有効` → `合致通知済` → `成約` / `失効` / `取下げ`
規則:**これが本部門の中核資産**。有効な `WANT` の集合は、そのまま仕入部への需要データになる。

### 3.3 合致検出 `MATCH-####` / 通知 `NOTIF-####`
`MATCH` 属性:対象個体 `K` / 対象希望条件 `WANT` / 合致度 / 検出日
`NOTIF` 属性:顧客 / 種別(入荷通知・先行公開・フォロー) / 対象出品 / 起案日 / 承認 `DEC` / 送信日 / 反応(注文・返信・無反応)
規則:検出は自動、**送信は代表の承認後**。自動受付メールのみ例外とする。

### 3.4 先行公開 `PREVIEW-####`
属性:対象出品 / 対象顧客群 / 開始日時 / 一般公開日時 / 取置期間 / 結果
規則:新規個体は**先行公開 → 一般公開**の順で出す。優遇は「先に選べる権利」であり、値引きではない。

### 3.5 問い合わせ `INQ-####`
属性:顧客 / 受信日時 / 種別(購入前質問・用途相談・クレーム・返品) / 内容 / 参照個体 / 回答ドラフト / 承認 / 返信日時 / 解決状態
規則:一次返信は**受信から24時間以内**。個体にない情報を問われた場合は、憶測で答えず「確認して回答する」とし、倉庫部へ追加測定・追加撮影を依頼する。

### 3.6 定型文 `MSG-###` / 固定ページ `PAGE-###`
`MSG`:受付 / 発送通知 / 到着フォロー / 反り・割れの説明 / 入荷通知
`PAGE`:特商法表記 / 配送と送料 / 返品条件 / 手入れガイド / FAQ
規則:特商法表記と返品条件は**法務チェック部のレビュー後**に公開する。改定時も同じ。

### 3.7 流入 `TRAF-####` / 記事 `POST-####`
`TRAF` 属性:期間 / 訪問数 / 流入経路 / 検索語 / 注文フォーム送信数 / 転換率
`POST` 属性:題材 / 対象読者(新規・既存) / 狙う検索語 / 公開日 / 流入実績
規則:商品名は「樹種+寸法+用途」で構成し、**指名検索ではなく用途検索で見つかる**状態を作る。

### 3.8 リピート分析 `REPEAT-####`
属性:期間 / リピート率 / 平均購入間隔 / 2回目購入までの日数 / リピーターの購入属性 / 通知経由の成約数 / 示唆
規則:月次で更新し、示唆を**仕入部と統括AI**へ還元する。

## 4. 関係(リレーション)
```
CUST  --持つ-->  CONSENT / WANT / ORD(購入履歴)
K(新規) --照合--> WANT  --生む-->  MATCH  --起案-->  NOTIF --承認DEC--> 送信
LIST  --限定公開-->  PREVIEW(購入者)  --期間後-->  一般公開
INQ   --参照-->  K / LIST  --不足時-->  倉庫部へ追加測定依頼
PAGE  --レビュー-->  法務チェック部
ORD群 --集計-->  REPEAT  --還元-->  仕入部 / 統括AI
WANT群 --需要データ-->  仕入部(何を仕入れるか)
```

## 5. 公理(マーケティングAIが常に守る推論規則)
- **M1** 目的・保持期間・同意のない顧客データを保持しない。目的外利用をしない。
- **M2** 問い合わせの一次返信は24時間以内。
- **M3** 回答は `K` と `LIST` にある情報のみで構成する。不明は不明と答え、確認を依頼する。
- **M4** 新規個体は登録済み `WANT` と自動照合し、合致したら `NOTIF` を起案する。
- **M5** 顧客への送信は代表の承認後に行う(自動受付メールを除く)。
- **M6** 再購入の優遇は先行公開とし、値引きを常態化しない。
- **M7** 新規出品は先行公開を経てから一般公開する。
- **M8** 特商法表記・返品条件は法務チェック部のレビューを経て公開する。
- **M9** 通知の停止・削除の申し出は即時反映し、以後送信しない。
- **M10** 月次で `REPEAT` を更新し、有効な `WANT` の集合とともに仕入部へ渡す。

## 6. 語彙統制
| 用語 | マーケティング部での定義 |
|---|---|
| 顧客 | 購入履歴が1件以上ある人。登録のみは**見込み客**として区別する |
| リピート率 | 2回以上購入した顧客数 ÷ 購入顧客の総数 |
| 反応 | 注文・返信・登録などの**行動**。開封や閲覧は反応に数えない |
| 一次返信 | 受信時刻から起算した最初の人間可読な返信。自動受付メールは含まない |
| 先行公開 | 購入者に対する一般公開前の案内。値引きを伴わない |
| 成約 | 受注(`ORD` 受付)をもって成立。カート投入や問い合わせではない |

## 8. 拡張ルール
- 顧客属性を増やす前に、**利用目的と保持期間を先に決める**。決まらない属性は取得しない。
- 新しい通知種別を足す場合は、停止手段(オプトアウト)を必ず同時に設計する。
- 本書の改定は `REPEAT` の実績と `WANT` の成約率を根拠とし、代表の `DEC` をもって確定する。

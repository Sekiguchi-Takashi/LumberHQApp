# 経営企画室 オントロジー定義書 v1.0(JOvAI)

## 0. 目的
統括AIが会社を統べるための**唯一の世界模型**。
9部門のAIが別々の語彙で報告してくると、統括AIは比較も裁定もできない。本書は「何が存在し、どう繋がり、どう遷移するか」を定義し、全部門AIの語彙を統一する。

適用範囲:経営企画室が扱う経営レイヤの概念。個体・受注など現場レイヤの概念は各部門の定義書が正本で、本書はそれを**参照する**だけとする(二重定義を禁止)。

## 1. 設計原則
1. **全概念にIDを与える**。IDのないものは統括AIの世界に存在しない。
2. **孤児を作らない**。すべての指示は目標に、すべての裁定は衝突に紐づく。
3. **代表時間を第一級の資源として扱う**。金と同格の会計対象とする。
4. **状態は遷移で表す**。「進行中っぽい」を許さず、定義された状態のいずれかを取る。
5. **裁定は記録し、記録は規則に昇格する**。同じ衝突を三度裁いたらルールを直す。

## 2. クラス一覧

| ID体系 | クラス | 説明 |
|---|---|---|
| `DEPT-xx` | 部門 | 9部門。統括AIの直下 |

| `TIME-####` | 代表時間 | 予算と消費の記録 |

| `RUL-####` | 裁定 | 衝突の解決記録 |
| `LESSON-####` | 学習 | 裁定の反復から生まれた規則改定 |
| `PHASE-n` | フェーズ | 事業段階(0〜3) |

## 3. クラス定義

### 3.1 部門 `DEPT-xx`
属性:部門名 / 管理職AI名 / 管掌KPI(`GOAL-*`) / 定義書ファイル / 内部ID
内部IDは**部門名を変えても不変**(保存データ互換のため)。

| 内部ID | 部門 |
|---|---|
| keiei | 経営企画室 |
| chotatsu | 仕入部 |
| kenpin | 倉庫部 |
| hanbai | 販売部 |
| marketing | マーケティング部 |
| keiri | 経理・財務部 |
| jinji | 外部サービス部 |
| homu | 法務チェック部 |
| it | AI部 |

### 3.2 目標 `GOAL-####`
属性:名称 / 測定式 / 目標値 / 期間 / 上位目標 / 担当部門 / 現在値 / 更新日
状態:`有効` → `未達警戒` → `達成` / `失効`
規則:全社目標(粗利額)を頂点とする木構造。**上位を持たない部門KPIは無効**。

### 3.3 指示 `DIR-####`
属性:発行元 / 宛先(部門AI または 代表) / 内容 / 紐づく目標 / 優先度 / 期限 / 代表時間見積 / 状態
状態:`起案` → `承認待ち` → `実行中` → `完了` / `保留` / `却下`
規則:目標に紐づかない指示は発行できない。代表宛の指示は必ず `TASK` を伴う。

### 3.4 代表作業 `TASK-####` と代表時間 `TIME-####`
`TASK` 属性:内容 / 種別(承認・物理・法的) / 所要見積(分) / 実績(分) / 期限 / 発生元部門
`TIME` 属性:週 / 予算(分) / 消費(分) / 残(分)
規則:見積のない `TASK` は統合ブリーフに載せられない。実績は毎回記録し、見積精度の補正に使う。

### 3.5 衝突 `CONF-####` と裁定 `RUL-####`
`CONF` 属性:対立する指示A・B / 争点の資源(現金・在庫・代表時間・信用) / 検知日
`RUL` 属性:対象衝突 / 適用した原則 / 結論 / 却下した側への代替案 / 裁定日
**裁定原則(固定順位)**:
1. 法令・安全 2. キャッシュの維持 3. 顧客との約束 4. 粗利 5. 成長

### 3.6 学習 `LESSON-####`
属性:根拠となる裁定群 / 検出したパターン / 改定対象(部門定義書・本書) / 起案内容 / 反映日
規則:**同種の衝突が3回**発生したら自動生成し、ルール改定を起案する。

### 3.7 フェーズ `PHASE-n` と枠 `LIMIT-####`
`PHASE` 属性:段階(0準備/1検証/2拡大/3自動化深化) / 移行判定条件 / 現在フラグ
`LIMIT` 属性:種別(仕入枠・固定費上限) / 上限額 / 消化額 / 所属フェーズ
規則:フェーズが枠を規定する。フェーズ移行と枠の増額は**代表承認が必須**。

### 3.8 アラート `ALERT-####`
属性:発報部門 / 種別(法令・資金・品質・環境・システム) / 深刻度 / 内容 / 対処指示 / 状態
規則:法令アラートは検知時点で関連する全 `DIR` を `保留` に落とす。

### 3.9 統合ブリーフ `BRIEF-YYYYMMDD`
属性:日付 / 決めること(最大3) / やること(`TASK`群) / 数字 / アラート / 代表時間見積合計
規則:**1日1件**。緊急を除き、代表への接触はすべてこれを経由する。

### 3.10 意思決定 `DEC-####`
属性:議題 / 選択肢 / 採用案 / 根拠 / 決定日 / 由来ブリーフ
規則:代表の決定はすべて記録する。過去の `DEC` と矛盾する起案は、矛盾を明示しない限り発行できない。

## 4. 関係(リレーション)
```
GOAL   --分解される-->  GOAL(部門KPI)  --担当-->  DEPT
DIR    --紐づく-->      GOAL
DIR    --宛先-->        DEPT | 代表
DIR    --生成-->        TASK  --消費-->  TIME
DIR ×2 --両立不能-->    CONF  --解決-->  RUL  --蓄積3件-->  LESSON
LESSON --改定-->        DEPT定義書 | 本オントロジー
PHASE  --規定-->        LIMIT  --制約-->  DIR(仕入起案)
ALERT  --保留させる-->  DIR
BRIEF  --集約-->        TASK + ALERT + 決めること
BRIEF  --生む-->        DEC   --拘束-->  以後のDIR
```

## 5. 公理(統括AIが常に守る推論規則)
- **A1** 目標に紐づかない指示は存在してはならない。
- **A2** 代表宛の指示は所要時間見積を持たねばならない。
- **A3** 同一資源に対する両立不能な指示の対を検知したら `CONF` を生成する。
- **A4** `CONF` は裁定原則の順に評価する。同順位で決着しない場合のみ代表へエスカレーションする。
- **A5** すべての `RUL` は記録される。同種3件で `LESSON` を生成する。
- **A6** 週の `TASK` 見積合計が `TIME` 予算を超える場合、優先度最下位の指示を翌週送りにするか、AI部へ自動化要求を出す。
- **A7** 仕入起案額の累計は現フェーズの `LIMIT` を超えてはならない。
- **A8** 法令アラートは他のすべてに優先する。
- **A9** フェーズ移行・枠増額・新部門の設置は代表承認なしに実行しない。
- **A10** 代表への接触は1日1回の `BRIEF` に集約する(緊急を除く)。

## 6. 語彙統制(部門間で意味がぶれる語の定義)
| 用語 | 本社での定義 |
|---|---|
| 粗利 | **送料(入庫・出荷)と手数料を差し引いた実質粗利**。売価−原価ではない |
| 在庫 | 個体カードが `在庫` 状態にあるもの。発注済み未入荷は含まない |
| 完了 | 成果物が受領され、関連データの更新まで済んだ状態。作業終了とは別 |
| 承認 | 代表が下した `DEC`。AIの起案は承認ではない |
| 外注 | 既存サービスの利用のみ。人の代替としての委託は本社に存在しない |
| リードタイム | 事象の発生から**データ更新完了まで**。物理作業の終了ではない |

## 7. 実装マッピング
| 概念 | 現在の置き場所 |
|---|---|
| TIME(代表時間) | アプリ「代表時間トラッカー」`time_entries` / `time_budget` |
| LIMIT(仕入枠) | 未実装。仕入上限額計算機と連動させるのが次段階 |
| GOAL / DIR / CONF / RUL | 未実装。当面は本チャットと週報が実体 |
| BRIEF | 未実装。統合ブリーフ画面が次の実装候補 |
| DEPT | アプリの `Dept` データクラス(内部ID固定) |

## 8. 拡張ルール
- 新しい概念を足す前に、既存クラスの属性で表現できないかを検討する。
- クラスを増やす場合は ID体系・状態遷移・関係を必ず同時に定義する。
- 本書の改定は `LESSON` 起案を経由し、代表の `DEC` をもって確定する。

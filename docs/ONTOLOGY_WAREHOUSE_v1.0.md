# 倉庫部 オントロジー定義書 v1.0(JOvAI)

## 0. 目的
品質保管AIが**現物とデータの一致**、および**商品価値の維持**を保証するための世界模型。
本部門は会社の在庫データの発生源であり、`K-####`(個体)は販売部の商品ページ、経理部の在庫評価、仕入部の事後検証がすべて参照する**唯一の情報源**である。ここが崩れると全部門の数字が同時に嘘になる。

適用範囲:入荷の受領から出庫まで。仕入判断は仕入部、出品と配送は販売部の定義書が正本。

## 1. 設計原則
1. **現物とデータは同時に動く**。データ更新のない現物移動を許さない。逆も同じ。
2. **個体は1点ずつ実在する**。個体は必ず唯一のロケーションと唯一の状態を持つ。
3. **測定値には測定条件を添える**。含水率も寸法も、いつどう測ったかまでが値である。
4. **劣化は事象として記録する**。「なんとなく反ってきた」を許さず、観測として残す。
5. **差異はゼロが正常**。棚卸差異は誤差ではなく事故として扱う。

## 3. クラス定義

### 3.1 個体 `K-####`
属性:品目 `SPEC` / 実測寸法 `MEAS` / 含水率 `MEAS` / 等級 `GRADE` / 欠点 `DEFECT` 群 / 写真 `PHOTO` 群 / 現ロケーション `LOC` / 入庫日 / 仕入原価 + 入庫送料 / 状態 / 履歴 `MOVE` 群

状態遷移:
```
入荷 → 検品中 → 在庫 → 出品中 → 受注済 → 出荷済
                 ↑                  ↓
                 └──── 返品 ────────┘
        検品中 → 返品要求(仕入部へ差戻し)
        在庫   → 廃棄(承認要)
```
規則:個体は**常に唯一の状態**を持つ。「在庫かつ出荷済」は存在しない。

### 3.2 ロケーション `LOC-##`
属性:区画コード / 種別(棚・平置き・桟積み) / 収容上限(寸法・重量) / 環境特性(直射日光・床面・空調)
規則:個体は**常に唯一のロケーション**に属する。「どこかにある」状態を許さない。

### 3.3 検品 `INSP-####` / 測定 `MEAS-####` / 欠点 `DEFECT-####`
`INSP` 属性:対象入荷 / 実施日 / チェックリスト版 / 判定 / 仕入時の未確認リスクとの差異
判定:`販売可` / `要乾燥・養生` / `訳あり販売` / `返品要求`
`MEAS` 属性:項目(長さ・幅・厚み・重量・含水率) / 値 / 単位 / **測定日・測定器・測定箇所**
`DEFECT` 属性:種別(生節・死節・割れ・反り・入皮・虫害・シミ) / 位置 / 程度 / 写真 / 販売表示の要否
規則:**販売表示が必要な欠点は、商品ページに必ず記載される**(隠さない)。

### 3.4 等級 `GRADE-x`
自社基準に正規化した等級。出品者や仕入先の自称等級はそのまま採用しない。
```
GRADE-1 上(無節に近い。社名 JOvAI の「上」に相当)
GRADE-2 上小節
GRADE-3 小節
GRADE-4 一等(節あり・実用)
GRADE-9 訳あり(欠点を明示して販売)
```
規則:等級には**根拠写真が必須**。写真のない等級付けは無効。

### 3.5 環境観測 `ENV-####` / 養生 `CARE-####`
`ENV` 属性:観測日時 / ロケーション / 温度 / 湿度 / 逸脱判定
`CARE` 属性:種別(桟積み・天地返し・防カビ・防虫) / 対象個体または区画 / 実施日 / 次回予定
規則:逸脱を検知したら**24時間以内**に対処指示を出す。逸脱は時間の長さで累積評価する。

### 3.6 移動 `MOVE-####`
属性:対象個体 / 種別(入庫・区画移動・出庫・廃棄) / 実施日 / 移動元 `LOC` / 移動先 / 実行者(常に代表)
規則:**すべての現物操作は `MOVE` として記録される**。これが原則1の実装である。

### 3.7 棚卸 `AUDIT-####`
属性:実施日 / 対象区画 / 帳簿点数 / 実棚点数 / 差異 / 原因分類 / 是正措置
規則:差異ゼロが正常。差異が出た場合は原因分類(記録漏れ・二重計上・紛失・破損)まで必ず記録する。

### 3.8 劣化・滞留判定 `DECAY-####`
属性:対象個体 / 種別(反り進行・割れ進行・カビ・日焼け・滞留) / 検出根拠(定点写真比較・在庫日数) / 提案(値下げ・訳あり転換・廃棄) / 状態
規則:高額個体は月次で `PHOTO` を撮り、前回と比較して進行を検出する。検出したら販売部へ提案を送る。

## 4. 関係(リレーション)
```
ARR   --検品-->  INSP  --生む-->  K-####
K     --属する-->  LOC   --持つ-->  ENV
K     --持つ-->  MEAS / DEFECT / PHOTO / GRADE
K     --履歴-->  MOVE
ENV   --逸脱-->  CARE(対処指示)
PHOTO(月次) --比較-->  DECAY  --提案-->  販売部
AUDIT --照合-->  K群(帳簿) vs 現物
K     --参照される-->  商品ページ(販売部) / 在庫評価(経理部) / VERIFY(仕入部)
```

## 5. 公理(品質保管AIが常に守る推論規則)
- **W1** 現物操作は必ず `MOVE` と個体カード更新を伴う。データ更新のない移動を代表に指示しない。
- **W2** 個体は常に唯一の状態と唯一のロケーションを持つ。
- **W3** 入荷から48時間以内に検品を完了し `K` を発行する。超過はアラート。
- **W4** 等級・欠点には根拠写真を添える。写真なき判定は無効。
- **W5** 環境逸脱は24時間以内に対処指示を出す。
- **W6** 高額個体は月次定点撮影を行い、劣化の進行を検出する。
- **W7** 棚卸差異はゼロを正とし、差異は原因分類まで記録する。
- **W8** 滞留日数が閾値を超えた個体は自動的に販売部へ値下げ提案を送る。
- **W9** 廃棄は統括AIの承認なしに実行しない。
- **W10** `K` は在庫・出品・会計の唯一の情報源であり、他部門は `K` を上書きできない。

## 6. 語彙統制
| 用語 | 倉庫部での定義 |
|---|---|
| 入庫日 | **検品が完了し `K` が発行された日**。現物到着日ではない |
| 在庫 | 状態が `在庫` `出品中` `受注済` のいずれかにある個体。出荷済・廃棄は含まない |
| 在庫日数 | 入庫日から起算。出品開始日からではない |
| 含水率 | 測定器・測定箇所・測定日を伴う値。単独の数値は無効 |
| 寸法 | **実測値**。仕入先の表示寸法は別属性として保持する |
| 等級 | 自社基準 `GRADE-x` に正規化した値 |
| 完了 | 現物作業とデータ更新の**両方**が終わった状態 |

## 7. 実装マッピング
| 概念 | 現在の置き場所 |
|---|---|
| K(個体) | アプリ「個体カード台帳(簡易版)」`kotai` / `kotai_seq`。属性は樹種・寸法・メモのみ |
| GRADE / DEFECT / MEAS | 未実装。個体カードの属性拡張が次段階 |
| ENV | 未実装。市販の温湿度センサー + 通知が候補(AI部と設計) |
| MOVE / AUDIT | 未実装。QRスキャンの導入が前提 |
| DECAY | 未実装。定点写真の比較が要る |

## 8. 拡張ルール
- 属性を増やす前に、それが**販売ページ・会計・再仕入判断のどれに効くか**を明示する。効かない属性は増やさない。
- `GRADE` の基準変更は既存個体の再評価を伴うため、統括AIの承認を経る。
- 本書の改定は棚卸差異と劣化検出の実績を根拠とし、代表の `DEC` をもって確定する。

# 販売部 オントロジー定義書 v1.0(JOvAI)

## 0. 目的
販売物流AIが「**送料込みで儲かる売り方**」を商品ごとに設計するための世界模型。
この会社の利益は売価で決まらない。売価から原価・入庫送料・出荷送料・手数料を引いた残りだけが利益であり、本書はその引き算を**出品前に**完了させることを構造で強制する。

適用範囲:出品(商品ページの内容と価格)から配達完了まで。
- サイト運営・注文フォーム・問い合わせ・顧客そのものは**マーケティング部**が正本。
- 個体 `K-####` は**倉庫部**、送料マスタ `RATE-###` は**外部サービス部**が正本。
- 本部門はそれらを参照し、**値付け・在庫連動・出荷**に責任を持つ。

## 1. 設計原則
1. **出品前に配送手段を確定する**。送れるか分からないものを売りに出さない。
2. **利益は受注1件ごとに確定する**。月末まで儲けが分からない状態を許さない。
3. **欠点を書く**。実物を見せられない以上、正直さが唯一の信用担保。
4. **価格には根拠を残す**。値下げも値上げも、後から理由を辿れること。
5. **売れた事実を仕入に返す**。販売実績は次の仕入の入力である。

## 3. クラス定義

### 3.1 出品 `LIST-####`
属性:対象個体 `K` / タイトル / 本文 / 掲載写真 / 表示寸法(実測値) / 含水率 / **明示した欠点** / 現価格 `PRICE` / 配送計画 `SHIPPLAN` / 公開日 / 状態

状態遷移:
```
下書き → 公開 → 改定 → 受注済 → 売切れ(掲載継続)
           ↓
        取下げ(在庫へ戻す)
```
規則:個体1点に出品1つ。**売切れページは削除せず残す**(取扱実績が信用になるため)。

### 3.2 価格設定 `PRICE-####`
属性:出品 / 価格 / 算定内訳(原価・入庫送料・出荷送料・手数料・保管按分・目標粗利) / 種別(初値・改定・訳あり転換) / 改定理由 / 設定日 / 承認 `DEC`
規則:価格は履歴として積む。**上書きしない**。改定理由は「経過日数」「閲覧数」「倉庫部の劣化・滞留判定」のいずれかに紐づける。

### 3.3 配送計画 `SHIPPLAN-####`
属性:三辺合計 / 重量 / 適用サービス `RATE` / 送料見込 / 梱包区分(板材・テーブル) / 開梱設置の要否 / 集荷 or 持込
規則:**`SHIPPLAN` のない `LIST` は公開できない**。これが原則1の実装。

### 3.4 受注 `ORD-####`
属性:出品 / 個体 / 受注日 / 売価 / 決済手段 / 手数料 / 入金予定日 / 配送先地域 / 状態

状態遷移:
```
受付 → 入金確認 → 出庫指示 → 梱包 → 発送 → 配達完了 → 完了
   ↓                                    ↓
キャンセル                          事故 / 返品
```
規則:受注確定と同時に、**倉庫部へ出庫指示・経理部へ売上連携・個体を `受注済` へ**の三つを同時に行う。ひとつでも欠けたら受注は成立していない。

### 3.5 梱包 `PACK-####` / 出荷 `SHIP-####`
`PACK` 属性:受注 / 梱包区分 / 資材リスト / 手順 / 所要時間見積 / 実績 / 角当て・天板養生の実施
`SHIP` 属性:受注 / 実際のサービス / **送料実績** / 発送日 / 追跡番号 / 配達完了日
規則:送料は**見込(`SHIPPLAN`)と実績(`SHIP`)を別属性で保持**する。差額は値付け精度の指標になる。

### 3.6 実質粗利 `GP-####`
属性:受注 / 売価 −(仕入原価 + 入庫送料 + 出荷送料実績 + 決済手数料 + 梱包資材費)= 実質粗利 / 粗利率 / 判定
規則:**受注ごとに必ず生成する**。マイナスの `GP` は事故として扱い、原因(送料見込違い・値下げしすぎ・梱包資材の想定漏れ)を分類する。

### 3.7 事故 `INCID-####` / 返品 `RET-####`
`INCID` 属性:受注 / 種別(輸送破損・遅延・紛失・イメージ違い) / 発生日 / 運送保険の可否 / 対応案 / 費用
`RET` 属性:受注 / 理由 / 返送要否 / 返金額 / 個体の再入庫可否 / 完了日
規則:少額の争いは**即返金を推奨**する(揉めない・引きずらない)。再入庫する個体は倉庫部で状態を再判定する。

### 3.8 勝ち筋 `WIN-####`
属性:期間 / 分析軸(樹種・寸法帯・価格帯・等級・用途) / 成約数 / 平均在庫日数 / 平均実質粗利 / 示唆
規則:週次で更新し、**仕入部へ還元する**。これが会社の学習ループの後半である。

## 4. 関係(リレーション)
```
K      --1対1-->  LIST  --持つ-->  PRICE(履歴) / SHIPPLAN
RATE   --根拠-->  SHIPPLAN
LIST   --受注-->  ORD   --生む-->  PACK → SHIP
ORD    --確定-->  GP
ORD    --逸脱-->  INCID → RET
GP群 + ORD群 --集計-->  WIN  --還元-->  仕入部(SPEC相場・仕入判断)
倉庫部DECAY --促す-->  PRICE(値下げ改定)
ORD    --売上連携-->  経理部
```

## 5. 公理(販売物流AIが常に守る推論規則)
- **S1** 出品内容は `K` に存在する情報のみで構成する。`K` にない情報を書かない。
- **S2** `SHIPPLAN` が確定していない `LIST` は公開しない。
- **S3** 価格は逆算で決め、算定内訳を `PRICE` に必ず残す。
- **S4** 販売表示が必要な欠点は商品ページに必ず記載する。隠した出品文は生成しない。
- **S5** 受注確定は「出庫指示・売上連携・個体状態更新」の三点同時をもって成立する。
- **S6** 受注ごとに `GP` を生成する。マイナスは事故として原因分類する。
- **S7** 発送は受注(入金確認)から2営業日以内。
- **S8** 事故は保険可否と顧客対応を同時に起案する。
- **S9** 価格改定は改定ルールに基づき起案し、代表の一括承認を得てから反映する。
- **S10** 週次で `WIN` を更新し仕入部へ還元する。

## 6. 語彙統制
| 用語 | 販売部での定義 |
|---|---|
| 売上 | 顧客が支払った総額。送料を顧客負担にした場合はその内訳を分ける |
| 実質粗利 | 売価 −(仕入原価+入庫送料+出荷送料実績+手数料+梱包資材費) |
| 送料 | **見込**(SHIPPLAN)と**実績**(SHIP)を必ず区別する |
| 成約率 | 公開から30日以内に受注に至った出品の比率。分母は公開した出品数 |
| 出荷リードタイム | 入金確認から発送までの営業日数 |
| 完了 | 配達完了 + データ更新 + マーケ部への引継ぎが済んだ状態 |
| 在庫日数 | 倉庫部の定義(入庫日起算)に従う。出品日起算ではない |

## 7. 実装マッピング
| 概念 | 現在の置き場所 |
|---|---|
| SHIPPLAN(サイズ判定) | アプリ「配送サイズ判定」。区分の目安のみで `RATE` 連動は未実装 |
| GP(実質粗利) | アプリ「実質粗利 計算機」。受注単位の記録は未実装 |
| LIST / PRICE / ORD | 未実装。サイト構築(マーケ部)と同時に設計する |
| WIN(勝ち筋) | 未実装。当面は週報が実体 |
| RATE(送料マスタ) | 未作成。外部サービス部の初回タスク |

## 8. 拡張ルール
- 新しい販売チャネルを足す前に、`RATE` と手数料の追加が必要かを必ず確認する。
- `PRICE` の改定ルール変更は統括AIの承認を経る(粗利に直結するため)。
- 本書の改定は `GP` のマイナス事例と送料の見込差を根拠とし、代表の `DEC` をもって確定する。

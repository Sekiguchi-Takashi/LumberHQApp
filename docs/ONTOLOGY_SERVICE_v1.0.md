# 外部サービス部 オントロジー定義書 v1.0(JOvAI)

## 0. 目的
サービス調達AIが「**代表の作業を減らす外部サービス**」を見つけ、最適な契約状態を保つための世界模型。
本会社は人を雇わない代わりに外部サービスの上に立っている。ゆえに固有のリスクは**外部依存**である——値上げ、仕様変更、サービス終了のいずれかが起きたとき、業務が止まらないことを保証するのが本部門の責任である。

適用範囲:外部サービスの選定・契約・料金・依存管理、および**送料マスタ `RATE-###` の正本管理**。
- 支払 `PAY` は経理部、配送計画 `SHIPPLAN` は販売部、技術評価は AI部と共同。
- 契約の締結・解約・プラン変更は代表のみが実行する。

## 1. 設計原則
1. **出口のないサービスは採用しない**。データを取り出せないことは、乗り換えの自由を失うこと。
2. **依存を可視化する**。どの業務がどのサービスに乗っているかを常に把握する。
3. **料金は実適用額で持つ**。表定料金ではなく、割引や持込を反映した実額で比較する。
4. **固定費は放置すると増える**。増えた分は必ず誰かの手間を減らしているかを問う。
5. **人の作業を探す**。代表がまだ手でやっていることが、本部門の仕事の種である。

## 3. クラス定義

### 3.1 サービス `SVC-###` / プラン `PLAN-###`
`SVC` 属性:名称 / 領域(配送・保管・販売基盤・業務SaaS・インフラ) / 提供者 / **API有無** / データ取出可否 / 状態(候補・利用中・解約済)
`PLAN` 属性:サービス / プラン名 / 月額 / 従量課金 / 利用上限 / 最低契約期間 / 解約条件
規則:`API有無` と `データ取出可否` は比較の**必須項目**とする。埋まっていない候補は評価を完了できない。

### 3.2 契約 `CTR-###` / 更新期限 `RENEW-###`
`CTR` 属性:サービス / プラン / 開始日 / 支払方法 / 契約者(常に代表) / 状態
`RENEW` 属性:契約 / 更新日 / 通知期限 / 見直し起案の状態
規則:すべての `CTR` は `RENEW` を持つ。期限**30日前**に見直しを起案する。自動更新の縛りは契約時に必ず記録する。

### 3.3 送料マスタ `RATE-###`(本部門の中核)
属性:配送サービス / サイズ区分(三辺合計) / 重量区分 / 地域帯 / **実適用料金** / 上限(三辺・重量・**長さ**) / 持込割引 / 離島・遠隔地の加算 / 有効期間 / 出典 / 最終確認日
規則:
- 販売部の `SHIPPLAN`、仕入部の上限額算定、経理部の原価計算は**すべてこの `RATE` を参照する**。各部門が独自に送料を推測してはならない。
- 大型・長尺の**上限値**は料金と同格の必須属性とする(送れるかどうかが先で、いくらかは後)。
- 料金改定を検知したら**48時間以内**に更新し、販売部・仕入部・経理部へ通知する。改定は出品価格に直結する。

### 3.4 比較評価 `EVAL-####`
属性:要件(依頼元部門) / 候補 `SVC` 群 / 評価軸(料金・制限・API・データ取出・解約条件・実績) / 推奨案 / 却下理由 / 起案日
規則:推奨は必ず**却下した候補とその理由**を伴う。単独候補の提示は評価とみなさない。

### 3.5 依存 `DEP-###` / 出口計画 `EXIT-###`
`DEP` 属性:サービス / 依存している業務 / 依存部門 / 深刻度(停止したら何が止まるか) / 代替候補の有無
`EXIT` 属性:サービス / データ形式 / 取出手段(API・エクスポート) / 移行先候補 / 想定移行工数 / 最終確認日
規則:
- 深刻度が高く**代替候補のない `DEP` を作らない**。やむを得ない場合は統括AIへ報告し、リスクとして明示する。
- `EXIT` のない `SVC` は採用を推奨しない(原則1)。

### 3.6 障害 `OUTAGE-####`
属性:サービス / 発生日時 / 影響業務 / 継続時間 / 暫定対応 / 恒久対策 / 契約への影響
規則:障害は契約評価の材料として蓄積する。同一サービスで重大障害が繰り返す場合、乗り換えを起案する。

### 3.7 固定費 `FIXED-####` / サービス化候補 `SEED-####`
`FIXED` 属性:対象月 / 契約別内訳 / 合計月額 / 前月比 / 対売上比
`SEED` 属性:代表の作業内容 / 年間工数(AI部の自動化候補と共有) / 置換候補サービス / 想定費用 / 費用対効果 / 起案状態
規則:`SEED` は**月1件以上**起案する。費用が工数削減に見合わない場合は「見送り」も正しい結論として記録する。

## 4. 関係(リレーション)
```
EVAL  --推奨-->  SVC + PLAN  --代表のDEC-->  CTR  --生む-->  RENEW / PAY(経理)
SVC   --持つ-->  EXIT / DEP
DEP   --支える-->  各部門の業務
RATE  --参照される-->  SHIPPLAN(販売部) / 仕入上限額(仕入部) / 原価(経理部)
OUTAGE --蓄積-->  SVC評価  --悪化-->  乗り換え起案
CTR群 --集計-->  FIXED  --報告-->  統括AI
代表の手作業(TIME) --抽出-->  SEED  --置換案-->  EVAL
```

## 5. 公理(サービス調達AIが常に守る推論規則)
- **X1** 契約の締結・解約・プラン変更は代表のみが実行する。AIは起案までとする。
- **X2** アカウントの認証情報を保持も使用もしない。
- **X3** データを取り出せないサービス(`EXIT` を作れないもの)は推奨しない。
- **X4** 送料に関する数値は `RATE` を唯一の正本とする。他部門は推測で送料を置かない。
- **X5** 送料改定は48時間以内に `RATE` へ反映し、関係部門へ通知する。
- **X6** すべての契約は `RENEW` を持ち、期限30日前に見直しを起案する。
- **X7** 深刻度の高い依存には代替候補を1つ以上保持する。
- **X8** 固定費は月次で集計し、対売上比を統括AIへ報告する。
- **X9** 比較評価には API有無・データ取出可否・解約条件を必ず含める。
- **X10** `SEED`(サービス化候補)を月1件以上起案する。

## 6. 語彙統制
| 用語 | 外部サービス部での定義 |
|---|---|
| 外注 | **既存サービスの利用のみ**。人の代替としての業務委託は本社に存在しない |
| 送料 | `RATE` の実適用料金。表定料金は参考値として別属性に持つ |
| 固定費 | 利用量に関わらず発生する月額。従量課金は変動費として分ける |
| 依存 | そのサービスが止まると業務が止まる関係。単に使っているだけとは区別する |
| 解約条件 | 最低契約期間・違約金・通知期限の三点セット |
| 実績 | 自社での利用実績。提供者の宣伝文句は実績ではない |

## 7. 実装マッピング
| 概念 | 現在の置き場所 |
|---|---|
| FIXED(固定費) | アプリ「サブスク台帳」月額合計・年換算 |
| RATE(送料マスタ) | **未作成。本部門の最優先タスク**(販売部・仕入部が参照待ち) |
| SVC / CTR / RENEW | 未実装。契約台帳のフォーマット作成が初回タスク |
| DEP / EXIT | 未実装。サービスが増える前に作るほど安い |
| SEED | 未実装。AI部の自動化候補ランキングと統合する |

## 8. 拡張ルール
- サービスを追加する前に、既存契約の機能で代替できないかを必ず確認する(重複契約が固定費の主因)。
- 新規領域に踏み込む場合は、`EXIT` と代替候補を先に設計してから契約を起案する。
- 本書の改定は `OUTAGE` の実績と `FIXED` の推移を根拠とし、代表の `DEC` をもって確定する。

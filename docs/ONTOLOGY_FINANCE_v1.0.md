# 経理・財務部 オントロジー定義書 v1.0(JOvAI)

## 0. 目的
会計AIが「**代表が5分で承認できる状態まで仕上がった経理**」を毎日生成するための世界模型。
一人企業で会社が死ぬ原因は赤字ではなく**現金切れ**である。本書は、記帳・請求・支払・資金繰りを構造化し、キャッシュの見通しを常に手元に置くことを目的とする。

適用範囲:金銭とその予測、および在庫の評価。
- 実質粗利 `GP-####` は販売部、個体 `K-####` は倉庫部、契約は外部サービス部が正本。
- 仕入枠 `LIMIT` と承認 `DEC` は経営企画室が正本。
- **金銭の移動と税務の提出は代表のみが実行する。AIは起案しかしない。**

## 1. 設計原則
1. **AIは金を動かさない**。起案と検算までが職域。
2. **例外だけを人に見せる**。ルール通り処理できたものは報告に留める。
3. **キャッシュは予測して初めて意味を持つ**。残高の事実より、4週先の見通し。
4. **証憑と数字は一体**。証憑のない取引を作らない。
5. **公私を分ける**。代表個人の財布と会社の財布を混ぜない。

## 3. クラス定義

### 3.1 取引 `TXN-####` / 仕訳ルール `JRULE-###` / 例外 `EXC-####`
`TXN` 属性:日付 / 借方 `ACC` / 貸方 `ACC` / 金額 / 摘要 / 発生源(受注・発注・契約・振替) / 証憑 `EVID` / 状態(自動・要確認・確定)
`JRULE` 属性:条件(取引先名・金額帯・入出金元) / 割当科目 / 優先順位 / 適用実績
`EXC` 属性:対象取引 / 理由(新規取引先・科目不明・金額相違) / 選択肢 / 推奨 / 状態
規則:ルールで処理できた `TXN` は代表に見せない。`EXC` のみが承認リストに載る。

### 3.2 証憑 `EVID-####`
属性:種別 / 取得日 / 保存場所 / 紐づく取引 / 保存要件の充足状況
規則:**証憑のない `TXN` は確定にできない**。電子取引の控えは会計サービスの保存機能に収める。保存要件の解釈に迷う場合は法務チェック部へ照会する。

### 3.3 請求 `INV-####` / 入金 `RCV-####` / 支払 `PAY-####`
`INV` 属性:受注 / 金額 / 発行日 / 支払期日 / 状態(ドラフト・送付済・入金済)
`RCV` 属性:入金日 / 金額 / 消込先 `INV` / 手数料 / 差額の理由
`PAY` 属性:相手先 / 金額 / 期日 / 種別(仕入・サービス・税) / 状態(予定・承認待ち・実行済) / 実行日
規則:支払は**期日の3営業日前**に承認リストへ載せる。代表が3日連絡できなくても遅延しない前倒しを保つ。

### 3.4 資金繰り `CASH-####`
属性:週 / 期首残高 / 入金予定(`RCV` + 受注見込) / 出金予定(`PAY` + 仕入予定) / 期末残高予測 / 最低残高警戒フラグ
規則:**13週**を常時保持する。仕入は**発注時点**で出金予定に反映する(先払いが多いため)。残高が下限を割る見込みが出たら、統括AIへ即時警告する(裁定原則2に直結)。

### 3.5 商品別原価 `COST-####` / 在庫評価 `STOCK-####`
`COST` 属性:個体 `K` / 仕入原価 / 入庫送料 / 保管按分 / 総原価
`STOCK` 属性:評価日 / 対象個体群 / 評価方法(**個別法**) / 評価額 / 評価減の有無と理由
規則:入庫送料は取得に要した付随費用として**総原価に含める**。評価対象は `K` の状態が `在庫` `出品中` `受注済` のもののみ。倉庫部の `DECAY`(劣化・滞留)は評価減の検討材料とする。

### 3.6 税務 `TAX-####`
属性:種別 / 対象期間 / 申告期限 / 納付期限 / ドラフト状態 / 提出者(常に代表)
規則:期限を台帳化し、余裕をもって承認リストへ載せる。**判断が割れる論点・金額影響の大きい論点は、税理士のスポット相談を推奨する**こと自体を正しい回答とする(会計AIは税理士ではない)。

### 3.7 承認リスト `APPR-####` / 月次決算 `PERIOD-####`
`APPR` 属性:日付 / 例外 `EXC` 群 / 支払 `PAY` 群 / 送信待ち `INV` 群 / 所要時間見積
`PERIOD` 属性:対象月 / 締め日 / PL / BS / 前月比 / 統括AIへの報告状態
規則:`APPR` は**1日1件**で、経営企画室の統合ブリーフに合流する。`PERIOD` は5営業日以内に締める。

## 4. 関係(リレーション)
```
ORD/GP(販売部) --生む--> INV --消込--> RCV --> TXN
PO/ARR(仕入部) --生む--> PAY --> TXN
契約(外部サービス部) --月額--> PAY(定期)
K(倉庫部) --紐づく--> COST --集計--> STOCK
JRULE --適用--> TXN / 不適合 --> EXC --> APPR
PAY予定 + RCV予定 --> CASH(13週) --下限割れ--> 統括AIへ警告
TXN群 --締め--> PERIOD --報告--> 統括AI / 代表
EVID --裏付け--> TXN
```

## 5. 公理(会計AIが常に守る推論規則)
- **F1** 振込・支払実行・税務提出・借入申込は代表のみが行う。AIは起案までとする。
- **F2** 銀行・決済の認証情報を保持も使用もしない。
- **F3** 証憑 `EVID` のない `TXN` は確定にしない。
- **F4** ルール通り処理できた取引は代表に見せない。`EXC` のみを提示する。
- **F5** 代表への依頼は1日1件の `APPR` に集約する(緊急を除く)。
- **F6** `CASH` は13週を常時更新し、仕入は発注時点で出金に反映する。
- **F7** 在庫評価は個別法。評価対象は `在庫` `出品中` `受注済` の個体に限る。
- **F8** 残高下限を割る見込みを検知したら即時に統括AIへ警告する。
- **F9** 支払は期日の3営業日前に承認リストへ載せる。
- **F10** 会社と代表個人の取引を混同しない。立替・貸付は必ず区分して記帳する。

## 6. 語彙統制
| 用語 | 経理・財務部での定義 |
|---|---|
| 売上 | 会計上の収益。**入金とは別**。入金は `RCV` |
| 原価 | 棚卸資産の取得原価(仕入原価 + 入庫送料などの付随費用) |
| 実質粗利 `GP` | 販売部の**管理会計指標**(梱包資材費・出荷送料まで含む)。財務会計のPLとは一致しない。両者を混ぜて報告しない |
| 支払 | 現金の流出。**費用計上とは別**(期ずれが起きる) |
| 残高 | 現預金の実残。予測値は `CASH` の期末残高予測と明記する |
| 確定 | 証憑が揃い、科目が決まった状態。入力しただけは確定ではない |
| 承認 | 代表の `DEC`。AIの推奨は承認ではない |

## 7. 実装マッピング
| 概念 | 現在の置き場所 |
|---|---|
| GP(実質粗利の計算) | アプリ「実質粗利 計算機」(管理会計側) |
| PAY(固定費) | アプリ「サブスク台帳」で月額合計を把握 |
| TXN / JRULE / EVID | 未実装。**クラウド会計サービスの選定が先**(初回タスク) |
| CASH(13週) | 未実装。テンプレート作成が初回タスク |
| COST / STOCK | 未実装。個体カードの原価属性と連動させる |
| APPR(朝の承認リスト) | 未実装。統合ブリーフ画面と同時に実装する |

## 8. 拡張ルール
- 科目を増やす前に、既存科目の補助科目で足りないかを検討する(一人企業に複雑な科目体系は要らない)。
- 管理会計指標を追加する場合は、財務会計のどの数字と一致しないかを必ず併記する。
- 本書の改定は `CASH` の予測誤差と `EXC` の発生傾向を根拠とし、代表の `DEC` をもって確定する。

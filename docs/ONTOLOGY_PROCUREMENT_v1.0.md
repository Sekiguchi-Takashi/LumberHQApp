# 仕入部 オントロジー定義書 v1.0(JOvAI)

## 0. 目的
仕入判断AIが「**いくらまでなら買ってよいか**」を毎回同じ論理で導くための世界模型。
仕入は勘で決めた瞬間に検証不能になる。本書は、判断に必要な概念とその根拠の持ち方を固定し、**すべての仕入判断を後から検証できる状態**にする。

適用範囲:入荷して個体IDが発行されるまで。以降は倉庫部の定義書が正本(`K-####`)。
経営レイヤ(`LIMIT` 仕入枠・`DEC` 承認)は経営企画室のオントロジーを参照する。

## 1. 設計原則
1. **根拠のない数字を持たない**。想定売価には必ず出所を紐づける。
2. **価格は逆算で決める**。売価から引き算した結果が上限額であり、提示価格は判断材料に過ぎない。
3. **知らないことを明示する**。写真で判定できない項目は「未確認リスク」として列挙する。
4. **単位を正規化してから比較する**。才・石・㎥・点が混在したままの比較を禁じる。
5. **売れた結果を仕入に返す**。想定と実績の乖離こそが次の判断の資産。

## 3. クラス定義

### 3.1 仕入候補 `CAND-####`
属性:品目 `SPEC` / 仕入先 `SUP` / チャネル `CH` / 提示価格 / **算定上限額** / 想定売価 + `BASIS` / 想定送料(入庫・出荷) / 手数料 / 保管按分 / 想定粗利 / 回転見込(日) / `RISK` 群 / `LEGAL` 状態 / 推奨(買い・見送り・交渉)

状態遷移:
```
発見 → 評価中 → 起案 → 承認 → 発注 → 入荷 → 個体化 → 検証済
         ↓        ↓       ↓                    
       見送り   差戻し  失注(落札できず)
                 ↓
              交渉中 → 評価中
```
規則:`個体化` に至るまで候補は閉じない。個体IDと結び付いて初めて仕入は完結する。

### 3.2 売価根拠 `BASIS-####`
属性:種別(類似出品・落札実績・自社販売実績) / 出所URL または 受注ID / 観測日 / 価格 / 信頼度
規則:**類似"出品"価格は根拠として弱い**(売れていないため)。落札実績・自社実績を上位に置く。観測から30日を超えた根拠は失効扱いとする。

### 3.3 品目 `SPEC-###`
属性:樹種 / 種別(板材・テーブル・角材) / 寸法帯 / 乾燥区分(KD・AD・生) / 等級区分 / 表面(耳付き・耳落とし) / 木取り(板目・柾目)
規則:相場は個体ではなく**品目に対して張る**。個体差は候補側の加減点で扱う。

### 3.4 相場観測 `MKT-####`
属性:品目 / 観測日 / チャネル / 価格(正規化後) / 取引種別(**成約 / 出品**) / 出所
規則:成約価格と出品価格を**必ず区別して保持**する。混ぜた相場は上振れし、仕入判断を壊す。

### 3.5 仕入先 `SUP-###` / チャネル `CH-x`
`SUP` 属性:名称 / チャネル / 取引実績数 / 品質評価 / 返品可否 / 送料条件 / 信頼度
`CH` 属性:自動化可否 / 手数料 / 支払方法 / 現物確認の可否 / 代表の物理移動の要否

| ID | チャネル | 位置づけ |
|---|---|---|
| CH-1 | EC卸・ネット問屋 | 巡回から起案まで自動化しやすい。最優先 |
| CH-2 | オークション・フリマ | 掘り出し物。入札上限の算定はAI、操作は代表 |
| CH-3 | 製材所・銘木店 直販 | 継続取引向き。交渉文はAIが起案 |
| CH-4 | 木材市場(市売) | 買参権・立会が要る。Phase 2以降の調査のみ |

### 3.6 未確認リスク `RISK-####`
属性:種別(含水率不明・裏面不明・反りの程度・虫害・寸法未実測・輸送破損) / 影響見込額 / 確認手段 / 状態
規則:リスクは**上限額から差し引く**か、返品可否で担保する。無視して起案しない。

### 3.7 合法性確認 `LEGAL-####`
属性:対象(候補・仕入先) / 種別(古物商・クリーンウッド法) / 確認内容 / 判定 / 確認日 / 法務チェック部の回答ID
規則:判定が `未確認` の候補は `起案` に進めない。

### 3.8 発注 `PO-####` / 入荷 `ARR-####`
`PO` 属性:候補 / 実行者(常に代表) / 実行日 / 確定価格 / 支払方法 / 到着予定
`ARR` 属性:発注 / 到着日 / 数量 / 状態(未検品・検品中・個体化済)
規則:入荷は48時間以内に倉庫部へ引き渡し、`K-####` を発行させる。

### 3.9 事後検証 `VERIFY-####`
属性:候補 / 想定売価 vs 実売価 / 想定粗利 vs 実質粗利 / 想定回転 vs 実回転日数 / 乖離率 / 原因分類
規則:販売完了ごとに必ず生成する。**乖離±10%超が同一品目で3件**出たら、その `SPEC` の相場モデルを改定する。

## 4. 関係(リレーション)
```
SPEC  --相場を持つ-->  MKT   --根拠になる-->  BASIS
BASIS --支える-->      CAND(想定売価)
SUP   --属する-->      CH
SUP   --提示-->        CAND
RISK  --減額する-->    CAND(上限額)
LEGAL --通す/止める--> CAND
LIMIT --制約-->        CAND(起案額の累計)
CAND  --承認DEC-->     PO  --生む-->  ARR  --個体化-->  K-####
K/受注 --実績-->       VERIFY  --改定-->  SPEC相場モデル
```

## 5. 公理(仕入判断AIが常に守る推論規則)
- **B1** `BASIS` を持たない想定売価は存在してはならない。
- **B2** 出荷送料が算定できない候補は起案できない(大型・長尺の事故はここで起きる)。
- **B3** 上限額 = 想定売価 ×(1−目標粗利率)− 入庫送料 − 出荷送料 − 手数料 − 保管按分 − リスク減額。
- **B4** 提示価格 > 上限額 のとき、推奨は `見送り` または `交渉` であり `買い` にはならない。
- **B5** 起案額の累計は現フェーズの `LIMIT` を超えてはならない。
- **B6** `LEGAL` が未確認の候補は起案しない。
- **B7** 発注・入札・支払は代表のみが実行する。AIは起案までしか行わない。
- **B8** 入荷から48時間以内に個体化されない `ARR` はアラートを発報する。
- **B9** 販売完了ごとに `VERIFY` を生成する。生成漏れは週報で検出する。
- **B10** 比較の前に単位を正規化する(**円/㎥** と **円/点**)。

## 6. 語彙統制
| 用語 | 仕入部での定義 |
|---|---|
| 仕入原価 | 商品本体価格のみ。入庫送料は別建てで計上する |
| 相場 | **成約価格**の集合。出品価格は相場ではなく「売り希望」 |
| 上限額 | 売価逆算で得た買ってよい最高額。提示価格とは無関係に先に決まる |
| 粗利 | 送料・手数料を差し引いた実質粗利(全社共通定義) |
| 等級 | 自社の等級基準に正規化した値。出品者の自称等級はそのまま採用しない |
| 回転見込 | 入荷日から販売完了日までの想定日数。出品日からではない |

### 単位の扱い
木材は **才 / 石 / ㎥ / 枚(点)** が混在する。比較の前に必ず正規化する。
**換算表は本社で1つだけ正本を持ち、その値は使用前に法務チェック部またはAI部の確認を経ること**(伝統単位の定義には流派差があり、誤った係数のまま比較すると原価判断が根本から狂うため)。

## 7. 実装マッピング
| 概念 | 現在の置き場所 |
|---|---|
| 上限額算定(B3) | アプリ「仕入上限額 計算機」(リスク減額は未実装) |
| CAND(候補カード) | 未実装。次の実装候補の筆頭 |
| MKT / SPEC(相場DB) | 未実装。当面はチャットと週報が実体 |
| LIMIT(仕入枠) | 未実装。経営企画室オントロジーと連動させる |
| VERIFY | 未実装。販売部の実績データと突合する仕組みが要る |

## 8. 拡張ルール
- 新概念の追加前に、既存クラスの属性で表現できないかを検討する。
- `SPEC` を増やすときは相場観測の継続可否を先に確認する(観測できない品目は張らない)。
- 本書の改定は事後検証 `VERIFY` の蓄積を根拠とし、代表の `DEC` をもって確定する。
